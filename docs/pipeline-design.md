# 분석 파이프라인 설계

## 개요

```text
영상 입력
 -> FFprobe 메타데이터 확인
 -> FFmpeg 15초 간격 프레임 추출
 -> [A] 선택한 Ollama VLM 역명 OCR
 -> [B] 선택한 Ollama VLM 지장수목 Judge
 -> 구간 매핑 및 이벤트 병합
 -> 캡처·JSON·HTML·Markdown·PDF 리포트
```

Ollama는 앱 전용 `127.0.0.1:11435`에서 실행합니다. 모델은 사용자 데이터 폴더에 저장하고 `OLLAMA_NO_CLOUD=1`로 외부 클라우드 실행을 차단합니다.

## 모델 하네스

공통 출력은 JSON Schema로 강제합니다. 이미지+schema 조합을 처리하지 못하는 모델 템플릿에 대해서는 `format=json`, 일반 JSON 프롬프트 순으로 호환 재시도를 수행합니다.

- Qwen 하네스: 궤도와 전차선 geometry를 먼저 찾고 실제 픽셀 좌표로 bbox를 내도록 지시합니다. 판정 재현성을 위해 thinking을 끄고 temperature 0을 사용합니다.
- Gemma 4 하네스: 배경 경관과 국소 수목을 먼저 분리한 뒤 원근 오탐을 재검사하도록 지시합니다. 공식 권장값인 temperature 1.0, top_p 0.95, top_k 64를 사용합니다.
- OCR 하네스: 위험 판정과 대화를 분리하며, 실제로 보이는 한글만 전사하고 불명확하면 null을 반환합니다.

각 계열 안에서도 모델 크기별 지시를 분리합니다. 2B/E2B는 짧은 체크리스트와 320 토큰 출력을, 4B/E4B는 전체 체크와 448 토큰을, 8B/12B는 원근·필드 일관성 재검증과 512 토큰을 사용합니다.

## 지장수목 Judge

판정값은 `high`, `medium`, `low`, `none`입니다. 파이프라인에서 업무용 한글 위험도로 변환합니다. 녹색 픽셀이나 산·숲 배경만으로 위험을 높이지 않으며, 진행 방향의 특정 수목이 전차선 corridor에 들어온 경우 거리가 멀다는 이유만으로 낮추지 않습니다.

동일 모델 오류가 3회 연속 발생하면 해당 분석을 중단하고 메모리 부족, 미설치 모델, 이미지 미지원, Ollama 연결 오류를 구분해 리포트에 기록합니다.

## 역명 OCR

OCR은 Judge와 독립된 프롬프트로 120초 간격 실행합니다. `raw_text`, `station_name`, `confidence`를 받고 선택적 역명 사전과 결합해 영상 전체 구간을 매핑합니다.
