# 사용자 플로우

## 1. 최초 실행

사용자는 설치 마법사로 앱을 설치한 뒤 바로 실행한다.

첫 화면은 세 단계 스테퍼로 구성된다.

1. `영상 업로드`: 분석할 영상을 등록한다.
2. `분석`: 선택 파일명과 진행률을 확인하며 분석을 시작하거나 정지한다.
3. `보고서`: 분석이 끝난 영상의 PDF 리포트를 저장한다.

현재 단계만 파란색으로 강조되며, 완료된 단계와 아직 실행할 수 없는 단계는 회색으로
구분된다. 화면 아래의 `자세히 보기`를 누르면 영상 목록, 재생 화면, 통계와 탐지 프레임을
포함한 상세 화면으로 이동한다. 상세 화면 왼쪽 위의 뒤로가기 아이콘으로 첫 화면에
돌아올 수 있다.

## 2. API 설정

사용자는 왼쪽 사이드바 아래의 `API 및 모델 설정`에서 다음을 입력하거나 선택한다.

- OpenAI API key
- GPT vision 모델

대체 경로:

- `OPENAI_API_KEY` 환경변수
- `.env` 또는 `.env.local`

API key는 git, 릴리즈, 리포트에는 기록하지 않는다.

## 3. 영상 추가

사용자는 첫 화면의 `영상 업로드` 또는 상세 화면의 파일 선택 버튼으로 mp4, avi, mov,
mkv 파일을 추가한다. 메인과 상세 화면을 포함한 앱 창 어디에나 영상 파일이나 폴더를
끌어다 놓을 수 있다.

등록된 영상은 왼쪽 사이드바에 하나의 목록으로 표시된다. 영상을 선택하면 가운데
디테일 뷰가 해당 영상으로 전환된다.

앱은 다음을 표시한다.

- 영상 파일명
- 파일 크기
- 분석 대기/진행/완료/실패 상태
- 선택 영상 재생 화면

## 4. 분석 시작

사용자는 첫 화면의 `분석`을 누르거나 상세 화면에서 영상을 선택한 뒤 영상 플레이어 아래의
`분석 시작`을 누른다. 첫 화면의 분석 단계에는 선택 파일명과 진행률이 표시된다.
분석이 시작되면 같은 버튼이 `분석 정지`로 바뀌며, 중지를 요청하면 완료될 때까지
`중지 중` 상태로 잠긴다.

앱 동작:

```text
영상 메타데이터 확인
 -> FFmpeg 프레임 샘플링
 -> GPT OCR
 -> GPT VQA Judge
 -> 타임코드 기준 병합
 -> 캡처 저장
 -> PDF/HTML/Markdown/JSON 리포트 생성
```

한 번에 한 영상만 분석한다. 여러 영상을 동시에 등록할 수 있지만 시작/중지 제어는 영상별로 수행한다.

## 5. 결과 확인

분석 완료 후 오른쪽 사이드바 상단에는 통계, 그 아래에는 탐지 프레임 목록이 표시된다.
프레임을 선택하면 영상 플레이어가 해당 타임코드로 이동하고 가운데 상세 정보가 갱신된다.

앱은 다음을 표시한다.

- 이벤트 수
- 영상별 완료 상태
- 캡처 프레임
- 위험도
- 타임코드
- 근거 문장
- OCR 기반 구간 정보

위험 이벤트가 없으면 이벤트 영역에 “기준 위험 이상의 이벤트 없음” 안내를 표시한다.

## 6. PDF 리포트 저장

사용자는 첫 화면의 `보고서` 또는 상세 화면 오른쪽 사이드바 아래의 `PDF 리포트 저장`으로
원하는 위치에 리포트를 저장한다. 저장이 끝나면 앱 내부 PDF 미리보기가 즉시 열리며,
여러 페이지를 스크롤하거나 확대·축소해 확인할 수 있다.

PDF는 제공된 현장 REPORT 양식에 맞춰 분석일시, 영상명, OCR 추정 구간, 위험도별 탐지
건수를 분석현황으로 정리한다. 동일 영상 시점은 하나의 평가만 남기고, 각 OCR 추정 구간을
제목으로 표시한 뒤 해당 구간의 고유 탐지 프레임을 시간순으로 아래에 나열한다. 각 프레임은
위험도, 재생 시점, 영상명과 판단 근거를 함께 표시한다. 촬영일자, 킬로정, 사업소처럼 영상과
분석 결과에서 확인할 수 없는 항목은 출력하지 않는다.

리포트 산출물:

- `report.pdf`
- `report.html`
- `report.md`
- `observations.json`
- `events.json`
- `captures/`

## 예외 상태

### API key 없음

- 분석 시작 불가
- API 설정 창으로 이동
- 환경변수 또는 앱 설정 저장 안내

### OpenAI API 오류

- 반복 실패 시 분석 중단
- 리포트와 로그에 HTTP status 및 오류 요약 기록
- 401: API key 확인
- 429: rate limit 또는 quota 확인
- 모델 접근 오류: 선택 모델 변경 안내

### FFmpeg 없음

- 설치판에서는 번들 FFmpeg를 우선 사용
- 개발 실행에서는 시스템 FFmpeg 또는 `FFMPEG_PATH` 설정 필요

### 위험 이벤트 없음

- 진행률 100%와 success 상태 표시
- 이벤트 영역에 “기준 위험 이상의 이벤트 없음” 안내 표시
- 리포트는 정상 생성
